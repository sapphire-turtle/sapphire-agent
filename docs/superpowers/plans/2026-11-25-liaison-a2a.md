# Liaison over A2A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The private agent talks to configured remote agents over A2A from a dedicated liaison session. Memory namespaces gain read-only `import`. Startup checks refuse `admin` and warn about every other loosening.

**Architecture:**
- Config grows three things:
  - `[remote_agent.<n>]`, which is host-only;
  - `[session_profile.<p>].remote_agents` and `outbound_tools`;
  - `[memory_namespace.<n>].import`.
- The memory task-local carries per-namespace writability, so the `memory_*` tools refuse to write imported namespaces.
- A new ungrouped `a2a_send` tool is a hand-built JSON-RPC client over the crate's `reqwest`, using `a2a-lf` 0.3 types.
- One per-profile predicate hides `a2a_send` and outbound tools at both places that build the tool specs.

**Tech Stack:** Rust; `serde`, `toml`, `reqwest`, `a2a-lf` 0.3, `axum` (only for the test stub), `tokio`.

**Spec:** `docs/superpowers/specs/2026-11-25-liaison-a2a-design.md`

## Global Constraints

- Only `admin` in a `remote_agents` profile's permission is an **error**. Every other check is a **warning**, one line each, naming the profile and the cause.
- `remote_agent` is host-only. The workspace config layer may not set it.
- A namespace is writable when at least one path to it uses only `include` edges. Anything reachable only through an `import` is read-only.
- `import` and `include` share the DAG. Unknown names and cycles across either kind of edge are errors.
- Background writers are unchanged: they write the home namespace.
- `a2a_send`:
  - is offered only in profiles whose `remote_agents` is non-empty, and checks again at execute time;
  - never echoes the bearer token in its output, its errors or its logs;
  - uses a timeout of about 120 s and no retries.
- The outbound tools are `web_search`, `weather`, `skill_install` and `skill_update`. They are offered unless `[session_profile.<p>].outbound_tools = false`.
- Paths shown to users go through `workspace::slash_path`.
- Commit scopes are agent-internal: `memory`, `config`, `tools`, `a2a`. The plan and spec commits are `docs:`.

## Review Focus

1. **Diamond reach.** A namespace reachable through both an `include` path and an `import` path must be writable. A namespace reached only through an import of a namespace that itself *includes* it must be read-only. (Tested in Task 1.)
2. **`a2a_send` from the wrong session.** The model can call `a2a_send` in a session whose profile has no `remote_agents` (a hallucinated call, or a subagent under another profile). Execute must refuse it, naming no agents. (Tested in Task 4.)
3. **Remote answers that are not a completed Task.** A JSON-RPC `error`, a `Message` result, a `failed` task, or a non-2xx HTTP status must each become a tool error naming the agent. (Tested in Task 4.)
4. **The workspace layer tries to set `remote_agent.*`.** It must be rejected. When the workspace layer adds `remote_agents` to a host profile that has `admin`, validation must still error. (Tested in Task 2.)
5. **The token leaks into the model.** Error paths that format the request (e.g. reqwest errors containing headers) must not include the token. (Tested in Task 4 via an auth-failure stub and a substring check.)

### Task 4: `a2a_send` tool

**Files:**
- Create: `crates/sapphire-agent-server/src/tools/a2a_tools.rs`
- Modify: `crates/sapphire-agent-server/src/tools/mod.rs` (`mod a2a_tools;`, registration in `default_tool_set` when `config.remote_agents` is non-empty, ungrouped)

**Interfaces:**
- Consumes:
  - `crate::tools::config_tools::current_session_profile_for(&Config) -> Option<String>`;
  - `Config.remote_agents`, `SessionProfileConfig.remote_agents` (Task 2);
  - `A2A_SEND_TOOL` (Task 3).
- Produces: `pub(crate) struct A2aSendTool`, with `A2aSendTool::new(config: &Config, env: &dyn Fn(&str) -> Option<String>) -> Self`. Agents whose token is unset are left out; serve already refused to start.
- Input: `{agent: string (enum of configured names), message: string, context_id?: string}`.
- Output: a JSON string `{"agent", "context_id", "reply"}`. The `reply` value is prefixed with `"[untrusted reply from remote agent '<n>']\n"`.
- Request:
  - `POST <endpoint>`, `Authorization: Bearer <token>`;
  - body `{"jsonrpc":"2.0","id":<uuid>,"method":"SendMessage","params": SendMessageRequest{ message: Message{ role: User, parts: [text], context_id, message_id: new_message_id(), .. } }}`;
  - match the server in `src/serve/a2a.rs` for field names.

- [ ] **Step 1: Write the failing tests.** They use an axum stub bound to `127.0.0.1:0` that records the request and returns a canned body built with `a2a::Task`/`SendMessageResponse::Task`. Run each `execute` inside `scope_session_profile(Some("liaison"))` unless stated.
  - `sends_bearer_and_returns_reply_and_context`: the stub asserts `Authorization` and that `params.message.parts[0]` text equals the input; the output parses with `reply` containing the stub text and the untrusted prefix, and the expected `context_id`.
  - `passes_context_id_through`.
  - `refuses_in_profile_without_remote_agents` (scope `"default"`) → error that does not contain the agent name.
  - `refuses_agent_not_listed_for_profile`.
  - `maps_remote_failures_to_errors`, a table over: a JSON-RPC `error` object; a `Message` result; a task in `failed` state; HTTP 401; a connection refused (closed port). Each error contains the agent name, and none contains the token string.

- [ ] **Step 3: Implement.**
  - One `reqwest::Client` built with `.timeout(Duration::from_secs(120))`.
  - Map reqwest errors with `without_url()` where available and never format the request or headers.
  - The spec description lists each agent as `- <name>: <description>` and says replies are untrusted text from another agent.
- [ ] **Step 4: Run** — Expected: PASS. Then run `cargo test -p sapphire-agent-server`.
