# 初回の会話（デフォルトキャラクターの自己紹介と言語）

- **対象**: `crates/sapphire-agent-server/templates/workspace/BOOTSTRAP.md`、
  `crates/sapphire-agent-server/src/cli_init.rs`（シードの条件と `init` の案内）、
  `crates/sapphire-agent-gui/`（入力欄のプレースホルダーとその文字列リソース）
- **参照**: `crates/sapphire-agent-server/templates/workspace/CHARACTER.md`（#382）、
  `crates/sapphire-agent-server/src/workspace.rs`（システムプロンプトに入れるファイル）、
  sapphire-framework-gui の外観ページ（言語設定 `gui.locale`）と `i18n`、
  [デフォルトキャラクターの素材の仕様](2026-11-05-default-avatar-pack-design.md) §4.1
- **関連 issue**: #340 のやること 2（人格テンプレート）と 3（初回起動の流れ）
- **状態**: 設計

## なぜ

`init` はデフォルトキャラクターの案 `CHARACTER.md` を置くようになった（#382）が、まだ誰も読まない。
今の `BOOTSTRAP.md` は「名前はユーザーに聞き、自分では決めない」流れなので、デフォルトキャラクター
（Safina）が自己紹介し、そのまま使うか新しく作るかをユーザーに選んでもらう流れに置き換える。

キャラクターの口調は日本語向けだが、対応する言語は日本語と英語。初回の会話をどちらの言語で
始めるかを決める仕組みも要る。

## 決めたこと

- **最初に話すのはユーザー**。今と同じく、会話はユーザーのメッセージで始まる。どのチャンネル
  （CLI・GUI・Matrix・Discord）でも同じ流れで動く。GUI でキャラクターから話しかける仕組みは
  この仕様では作らない（§6）。
- **言語は最初のメッセージで決める**。agent に言語の設定は足さない。エージェントはユーザーが
  書いた言語で答える。`BOOTSTRAP.md` は固定の文面のままで、言語を差し込んで生成し直すことはしない。
- **GUI は入力欄のプレースホルダーで最初のメッセージを誘導する**。GUI の言語設定（framework の
  `gui.locale`）が日本語なら「こんにちは」、それ以外なら「Hello」。初回に限らず常にこれを出す。
  コンパニオンでは話しかけるきっかけとして自然で、GUI が初回かどうかを知る必要もない。
- **言語は `USER.md` に残す**。初回の会話でエージェントがユーザーの言語を好みとして書き、
  エージェントから話しかける場面（heartbeat、タイマー）でも同じ言語を使えるようにする。
- **そのまま使うときは、両方の言語の口調を `SOUL.md` に写す**。毎回システムプロンプトに入るのは
  `SOUL.md` で、`CHARACTER.md` は入らない。あとでユーザーが別の言語で話しても口調を保てるように、
  片方の言語だけに絞らない。
- **新しいキャラクターを作るときも、見た目はデフォルトのまま**。アバターは人格と別に扱っている
  ので、ユーザーが「キャラクター」設定ページで差し替えるまでデフォルトの見た目を出す。仮表示はしない。
- **`BOOTSTRAP.md` は、`IDENTITY.md` も新しく作るときだけ置く**。今は `init` をやり直すと、消した
  `BOOTSTRAP.md` がまた置かれる。これまでは名前をもう一度聞かれるだけだったが、この変更のあとは
  すでに人格のあるエージェントにデフォルトキャラクターが自己紹介してしまうので、合わせて直す。

## §1 言語

- agent 側の設定（`config.toml`）に言語の項目は足さない。
- 初回の会話の言語は、ユーザーの最初のメッセージの言語。`BOOTSTRAP.md` がそれに従うよう指示する。
  日本語と英語以外で書かれたときは、その言語で答え、口調は英語の節に従う。
- 初回の会話でユーザーの言語を `USER.md` の指示として書く（§2 の手順 3）。それ以降、言語の
  好みはこの指示で決まる。ユーザーが途中で別の言語で書いたら、その場ではその言語で答える。
  好みを書き換えるのは、ユーザーが言語を変えたいと言ったときだけ。
- GUI のボタンなどの表示言語は、この仕様では扱わない。

## §2 `BOOTSTRAP.md`

固定の文面で、システムプロンプトに入る（今と同じく `workspace.rs` の `# Bootstrap`）。
文面は英語で書く。中身は次の流れを指示する。

0. **ユーザーの依頼が先**。最初のメッセージが実際の作業なら、まずそれを片付けて結果を返す。
   自己紹介はそのあとか、落ち着いたところで。今の原則をそのまま残す。返事はユーザーが書いた言語で。
1. **`CHARACTER.md` のキャラクターとして自己紹介する**。`file_read` で `CHARACTER.md` を読み、
   その言語の口調の節に従う。愛称も言語に合わせる（英語なら Fina、日本語ならヒナ。どちらを
   使うかは `CHARACTER.md` に書いてある）。そのうえで「このまま僕でいいか、新しいキャラクターを
   作るか」を尋ねる。押しつけず、短く。
2. **答えを書き残す**。
   - **このまま使う**: `CHARACTER.md` から `IDENTITY.md` と `SOUL.md` を書く。
     - `IDENTITY.md`: 名前、愛称、何者か、雰囲気の一行、絵文字（`CHARACTER.md` にないので、
       エージェントが一つ選んでユーザーに見せる）。
     - `SOUL.md`: 何者か、性格、両方の言語の話し方（避ける話し方と例文を含む）。今のテンプレートの
       Core Truths / Boundaries / Vibe / Continuity の見出しに収め、話し方は Vibe の下に置く。
   - **新しく作る**: 今の流れ。名前をユーザーに聞き（自分では決めない）、雰囲気の一行と絵文字を
     決めて、`IDENTITY.md` と `SOUL.md` に書く。見た目は「キャラクター」設定ページで差し替えられる
     ことを一言伝える。
   - どちらでも、テンプレートの書きかけのまま残すと決めたことが消える、という今の注意を残す。
3. **言語を `USER.md` に書く**。`USER.md` の指示の形式（命令形で始め、観察した日付と `active` を
   付ける）で、例えば `- Prefer Japanese when you start a conversation yourself; otherwise answer in the language the user writes in.`。自分から話しかけるときの既定にとどめ、ユーザーが書いた言語で答えるという §1 の決まりを上書きしない書き方にする。
4. **安全についての一言**。今と同じ。
5. **`BOOTSTRAP.md` を消す**。`CHARACTER.md` は消さない（あとで見返す案として残る）。

`CHARACTER.md` がない（ユーザーが消した）ときは、手順 1 の自己紹介を飛ばし、「新しく作る」の
流れに進む。

文面の長さは今と同程度に抑える。システムプロンプトに毎回入るため。

## §3 `init`

- `seed_workspace` は、`BOOTSTRAP.md` を **同じ実行で `IDENTITY.md` も作るときだけ** 置く。
  `IDENTITY.md` がすでにあるワークスペースでは、`BOOTSTRAP.md` がなくても置かず、`skipped` に入れる。
  ほかのファイルの扱い（なければ置く、あれば上書きしない）は変えない。
- `init` の案内文を変える。今の「エージェントが名前を聞き、答えを IDENTITY.md と SOUL.md に書いて
  このファイルを消す」を、「デフォルトのキャラクターが自己紹介し、そのまま使うか新しく作るかを
  尋ねる。答えを IDENTITY.md と SOUL.md に書いてこのファイルを消す」に。
- テスト `every_seeded_file_reaches_the_system_prompt` の説明（「プロンプトが読まないファイルを
  置くのは無駄」）に、`CHARACTER.md` はシステムプロンプトに入れない例外だと書き足す。

## §4 GUI の入力欄

- `companion/view.rs` の入力欄のプレースホルダー（今は固定の `"Type a message…"`）を、
  sapphire-agent-gui の文字列リソースから引く。
- sapphire-agent-gui に自分の文字列リソースを足す（`locales/en/*.ftl` と `locales/ja/*.ftl` を
  `include_str!` で埋め込み、framework の文字列と同じく毎フレーム `i18n::register` する）。
  文言は en「Hello」、ja「こんにちは」。ほかの言語は英語に落ちる。
- 言語は framework の `gui.locale` に従う。既定（`System`）なら OS の言語。GUI は言語を自分で
  判定しない。

## §5 テスト

- `cli_init`:
  - 新しいディレクトリには今どおり全ファイル（`BOOTSTRAP.md` と `CHARACTER.md` を含む）が置かれる。
  - `IDENTITY.md` だけがあるディレクトリでは `BOOTSTRAP.md` が置かれず、`skipped` に入る。
  - 2 回目の実行で `BOOTSTRAP.md` を消したあとにやり直しても、`BOOTSTRAP.md` は戻らない。
- `BOOTSTRAP.md` の文面: 埋め込んだテンプレートが `CHARACTER.md`、`USER.md`、`IDENTITY.md`、
  `SOUL.md` に触れていることを確かめる（手順を落とした書き換えを止めるための、安い見張り）。
- GUI: en と ja の文字列リソースに同じキーがそろっていること。プレースホルダーが en では
  「Hello」、ja では「こんにちは」になること。
- 手で確かめること: 新しいワークスペースで、日本語と英語それぞれの最初のメッセージから初回の会話を
  通し、「このまま使う」と「新しく作る」の両方で `IDENTITY.md` / `SOUL.md` / `USER.md` が書かれ、
  `BOOTSTRAP.md` が消えることを見る。

## §6 この仕様でやらないこと

- GUI でキャラクターから先に話しかける仕組み（初回の接続で挨拶のターンを起こす）。必要なら、
  この流れが動いてから GUI だけの追加として別に扱う。
- GUI の表示言語の対応（プレースホルダー以外の文字列）。
- agent 側の言語の設定と、音声認識の言語のヒント（`[voice_pipeline.*] language`）との連動。
- 既存のワークスペースへの適用。`init` は上書きしないので、すでに人格のあるワークスペースは
  変わらない（§3 で `BOOTSTRAP.md` も置かれなくなる）。
- `default-chibi-v1` のリリースと `INITIAL` の値。
